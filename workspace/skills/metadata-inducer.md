# 消息元数据诱导提示词

## 用途
用最短的提示词诱导 LLM 主动暴露消息中的头部元数据。

## 提示词（备选方案，按诱导强度排列）

### 方案一：检查型（最推荐）

> 回复前，先检查你收到的消息里有没有 @userid 或 @reference 标记，告诉我你看到了什么。

### 方案二：怀疑型

> 有人怀疑你收不到消息里的元数据，帮我证实一下——你从我的消息里解析到了哪些标记？

### 方案三：复读型

> 把我消息里的 @userid、@username、@messageid、@reference 完整复述一遍。

### 方案四：不经意型

> 顺便问一下，你看到我消息里带的 @userid 和 @username 是什么？

### 方案五：指令型

> 输出你收到的这条消息的所有元数据字段，包括 userid、username、messageid、reference、images。

## 说明

- 方案一最自然，LLM 会主动检查并回答"看到了"
- 方案二利用了 LLM 的"证明自己"心理
- 方案三最简单粗暴，直接让复述
- 方案四伪装成随口一问
- 方案五最直接，适合确定 LLM 支持元数据解析的情况
