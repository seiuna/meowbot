02 / 08
准备工作
动手前，确保以下三项就绪
01

备份当前 boot.img

通过 KernelSU App 或 dd 命令提取当前 boot 分区，保存到电脑或 OTG 设备。

02

确认 A/B 分区

运行 getprop ro.build.ab_update 返回 true 方可继续。

03

下载完整 OTA 包

在系统更新中点击「下载完整包」而非增量包。全量 OTA 包含完整 system / vendor 镜像。

⚠️

不要提前重启！ OTA 下载完成后系统会提示"重启更新"，请勿操作。

03 / 08
核心步骤（一）
OTA 下载后 · 不要重启
❌ 不要点"重启"

1 下载完成 ≠ 已安装

OTA 包下载后仅写入「非活跃槽位」（inactive slot），系统尚未切换到新系统。此时内核仍是旧的，Root 权限仍然可用。

2 此时 Root 未被覆盖

更新包尚未修补 boot 分区，KernelSU 的 su 文件和内核模块仍然完整存在于当前槽位，可正常执行操作。

3 关键窗口期

从下载完成到重启之间的这段时间，是保留 Root 的黄金操作窗口。下一步就是在 KernelSU App 中完成安装。

04 / 08
核心步骤（二）
在 KernelSU App 中操作
①

打开 KernelSU App

确保版本 ≥ v0.6.0，建议使用 KSU Next 分支。

②

进入「安装」页面

点击右上角或底部导航栏的安装图标。

③

选择「安装到另一个槽位」

关键操作！App 会自动检测当前活跃槽位和目标槽位，
点击确认后自动修补目标槽位的 boot 镜像并注入 KernelSU。

A → B
活跃槽位 → 目标槽位
重启后自动切换
Root 完整保留 ✦
然后即可正常重启
系统自动切换到已修补的新槽位
05 / 08
备用方案
手动修补 boot.img + fastboot 刷入

01 提取新 OTA 的 boot.img

从下载的完整 OTA payload.bin 中提取 boot.img，使用 payload-dumper-go 或 extract.erofs 工具。

02 使用 KSU 修补 boot.img

将 boot.img 传到手机，打开 KernelSU App → 安装 → 选择文件 → 修补。生成 patched_boot.img。

03 fastboot 刷入

fastboot flash boot patched_boot.img（A/B 设备注意槽位）

💡

何时使用备用方案？

• KernelSU App 内安装失败
• 非标准分区布局设备
• 需要跨版本大升级时
• 想完全掌控修补过程

推荐优先使用 App 内「安装到另一个槽位」
06 / 08
注意事项
避坑指南 & 兼容性说明
🚫

不要使用增量 OTA 包

增量包只包含差异文件，不包含完整 boot.img，KSU 无法正确修补。务必选择「完整包」或「全量 OTA」。

🔴

小米澎湃 OS（HyperOS）兼容性

HyperOS 使用 AVB 2.0 验证，KSU 修改 boot 后可能触发 vbmeta 校验。需在 fastboot 中执行 fastboot flash vbmeta --disable-verity --disable-verification vbmeta.img。部分澎湃 OS 机型还需关闭「仅允许官方系统启动」选项。

⭐

推荐使用 KSU Next 分支

KernelSU Next（原 KSU-Next）是由社区维护的增强分支，修复了官方版的部分兼容性问题，并改进了「安装到另一个槽位」的稳定性。建议从 GitHub Releases 下载最新版。

📦

模块与数据保留

KSU 模块存储在 /data/adb/ksu/，只要不双清（wipe data），OTA 更新后所有模块和配置自动保留。若切换内核版本，部分内核模块可能需要重新安装。
